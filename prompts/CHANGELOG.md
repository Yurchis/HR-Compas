# Changelog промптів

Кожна версія промпту — окремий файл у `prompts/` (напр. `v1_<назва>.md`).
Опубліковані версії не редагуються: зміна = нова версія + запис нижче.

## v1 — `v1_baseline.md` (2026-10-26)
**Гіпотеза:** повний довідник у контексті + жорстка заборона вигадувати дає точні відповіді з посиланням на джерела.
- перша версія: відповідь лише за довідником, мова питання, умови застосування, джерела `[id]`
- очікуваний ефект: базова лінія для порівняння наступних версій

## v2 — `v2_structured.md` (2026-10-26)
**Гіпотеза:** вимога JSON-схеми (found/answer/sources/confidence) дає машинно-перевірювані відповіді та менше вигаданого.
- відповідь — JSON за схемою `hr_compass/schema.py`; джерела й впевненість — окремі поля
- для `found=false` явно прописана відмова з відсиланням до HR
- v1 лишається для порівняння (запуск із `structured_output.enabled = false`)

## v3 — `v3_country_clarification.md` (2026-11-01)
**Гіпотеза:** якщо країна співробітника невідома, а в контексті правила кількох країн, модель без явного правила
мовчки обирає одну з них (прогін gpt-4o-mini 2026-11-01: 10/10 питань `qNN-any` — відповідь за випадковою країною).
Явне правило «кілька країн у фрагментах і країну не названо → уточнювальне питання» прибирає такі хибні відповіді.
Окремо: відмови українською на англійські питання (у v2 — 1/8 за прогін) мають зникнути від явного правила мови.
- на базі v2; нова схема відповіді `hr_answer_v3` (`hr_compass/schema.py`, `HRAnswerV3`): поле `needs_clarification`;
  при `true` — `found=false`, `sources=[]`, в `answer` — питання про країну. Пайплайн повертає таку відповідь як
  `clarification` (у `evaluate` — колонка «Тип відповіді»)
- окремий блок «Мова відповіді»: мова `answer` = мова питання, для відповіді, відмови й уточнення; мова інструкцій і
  довідника не впливає
- схему задає перший рядок файлу `<!-- schema: hr_answer_v3 -->` (його не бачить модель); v1/v2 без змін
- очікуваний ефект: `qNN-any` → `clarification` (тип відповіді ~100%), мова відповіді = мова питання; точність на
  питаннях із профілем — як у v2. Вартість не зменшується: контекст для `qNN-any` — усі три довідники

## intake v1 — `intake_promt.md` (2026-10-27)
**Гіпотеза:** окремий дешевий виклик, що визначає мову, тематику й профіль співробітника, дозволяє не гнати поза-тематичні питання через довідник (~30k токенів) і звузити контекст за країною/підкомпанією.
- вихід — JSON за `hr_compass/intake.py` (`language`, `in_scope`, `country`, `sub_company`, `needs_clarification`, `clarifying_question`)
- країна/підкомпанія заповнюються лише якщо названі прямо; уточнення — лише коли без нього відповідь буде хибною
- не змінює відповідні промпти v1/v2

## intake v2 — `intake_v2_en.md` (2026-10-31)
**Гіпотеза:** інструкції англійською моделі виконують точніше й з меншою кількістю токенів, ніж українською.
- дослівний переклад intake v1 англійською; поля, значення й правила без змін
- `chat.py` за замовчуванням використовує v2; v1 доступна через `--intake-prompt prompts/intake_promt.md`
- очікуваний ефект: та сама класифікація, менше токенів на виклик
